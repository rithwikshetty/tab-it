## 1. Screen and flow inventory

### Shared presentation, navigation, and formatting

- [ ] Keep the four tabs in order, "Friends", "Trips", "Activity", "Settings". Start on Trips. Friends, Trips, and Activity each keep an independent navigation stack. Show the tab bar at the tab root and trip/friend detail, and hide it on deeper detail/editor routes. Settings has its own navigation stack. Evidence: `Apps/Tab/Sources/Tab/Screens/RootView.swift:45`, `Apps/Tab/Sources/Tab/Screens/RootView.swift:86`, `Apps/Tab/Sources/Tab/Screens/RootView.swift:243`.
- [ ] Preserve routes for trip, friend identity, new expense in a container, global new expense picker, edit expense, expense detail, settle up with optional suggestion, edit settlement, and settlement detail. Back navigation returns to the originating stack. The global picker is replaced by the expense editor, so saving returns to the tab root. Evidence: `Apps/Tab/Sources/Tab/Screens/RootView.swift:8`, `Apps/Tab/Sources/Tab/Screens/RootView.swift:253`.
- [ ] Use the sage design tokens, category colors/icons, semantic green for money lent or owed to the user, warning color for borrowed money, and slate for settlements. iOS forces light appearance and portrait orientation. Keep long amounts legible and preserve safe-area clearance below floating actions. Evidence: `Apps/Tab/Sources/Tab/Theme/SageColors.swift:1`, `Apps/Tab/Sources/Tab/TabApp.swift:54`, `Apps/Tab/Sources/Tab/Info.plist:46`, `Apps/Tab/Sources/Tab/Components/Fab.swift:1`, `Apps/Tab/Sources/Tab/Components/ExpenseRow.swift:10`.
- [ ] Display a currency's distinct symbol followed by a locale-grouped amount with exactly its minor-unit fraction digits. If the symbol equals the code, show `CODE value`. Signed formatting prefixes a minus before the symbol. Do not convert or add different currencies. Input strings use ungrouped decimal text; empty amount placeholders are the currency-formatted zero. Evidence: `Apps/Tab/Sources/Tab/Models/MoneyFormatter.swift:11`, `Apps/Tab/Sources/Tab/Models/MoneyFormatter.swift:127`, `Apps/Tab/Sources/Tab/Models/MoneyFormatter.swift:151`.
- [ ] Amount entry accepts digits, dot, and comma. With both separators, the last occurring separator is decimal and the other is grouping. Multiple dots alone or multiple commas alone are removed as grouping. A single comma becomes a dot. Stop at the allowed fraction count. A zero-decimal currency drops the decimal point and following fraction rather than concatenating digits. Currency changes preserve numeric value at the new precision. Share/percentage inputs accept two decimal places independent of money precision. Evidence: `Apps/Tab/Sources/Tab/Models/MoneyFormatter.swift:35`, `Apps/Tab/Sources/Tab/Models/MoneyFormatter.swift:86`, `Apps/Tab/Sources/Tab/Models/MoneyFormatter.swift:99`.
- [ ] Treat an expense date as a calendar day. Wire it as `yyyy-MM-dd`, store the Swift representation at noon UTC, render its calendar day in UTC, and bridge that same named day into local date pickers. Settlements, creation/edit times, and activity are instants rendered in local time. Expense detail uses `d`, lowercase `MMM yyyy`, and long date; creation/edit detail uses medium date plus short time. Evidence: `Apps/Tab/Sources/Tab/Models/ExpenseDates.swift:8`, `Apps/Tab/Sources/Tab/Screens/ExpenseDetailView.swift:177`, `Apps/Tab/Sources/Tab/Screens/ExpenseDetailView.swift:565`, `Apps/Tab/Sources/Tab/Screens/SettlementDetailView.swift:254`.
- [ ] In member pickers, put the current person first, then joined people before pending people, then compare display names case-insensitively. Use "You" for the current person, but use their real name for avatar initials. Retain removed people for historical labels and balances. Evidence: `Apps/Tab/Sources/Tab/Models/EntityViewState.swift:477`, `Apps/Tab/Sources/Tab/Models/ViewState.swift:3`, `Apps/Tab/Sources/Tab/Models/Entities.swift:70`.
- [ ] Avatar initials are the first trimmed display-name character uppercased, or "?" for blank. Tone is one of terracotta,sage,sand,slate, selected by wrapping byte sum modulo four, using UUID bytes for claimed/local people or UTF-8 email bytes for pending friend identity. Max-four avatar groups show all four if exactly four, otherwise three initials and `+{remaining}`. Evidence: `Apps/Tab/Sources/Tab/Models/AvatarTone.swift:3`, `Apps/Tab/Sources/Tab/Components/Avatar.swift:59`.
- [ ] Invite/add email validation differs from auth's service validation. Shared EmailValidator trims/lowercases, rejects `|`, requires nonempty local part, a dot in the remaining domain, and no trailing dot; it does not explicitly reject every whitespace/multiple-@ form or cap length. Preserve valid addresses while aligning release form validation with the exact server limits. Evidence: `Apps/Tab/Sources/Tab/Models/EmailValidator.swift:7`, `Apps/Tab/Sources/Tab/Services/AuthService.swift:376`.
- [ ] Preserve six built-in categories in order: "Food & Drink", "Transport", "Lodging", "Activities", "Shopping", "Other". Their fixed IDs begin `00000001` through `00000006` and end `-0000-0000-0000-000000000000`; their icon keys are `bowl-food`, `car-profile`, `bed`, `mask-happy`, `shopping-bag`, `tag`. The current editor exposes built-ins, although the server can return custom categories. Evidence: `Apps/Tab/Sources/Tab/Models/DefaultCategories.swift:1`, `supabase/sql/04_categories.sql:50`, `Apps/Tab/Sources/Tab/Screens/ExpenseEntryView.swift:19`.

### Writes, constraints, RLS, and retention

- [ ] Direct writes used by iOS are group trip `UPDATE`, settlement `UPSERT onConflict:id`, expense/settlement tombstone `UPDATE`, mute `UPSERT onConflict:trip_id,user_id`, unmute `DELETE`, and push-device `DELETE` filtered by self and token. Profiles, new trips, memberships, non-group containers, full expense aggregates, push registrations, activity cursor, and invite actions use RPCs. There is no direct trip-person insert/update/delete, no client activity write, and no current category push. Evidence: `Apps/Tab/Sources/Tab/Services/SyncService.swift:904`, `Apps/Tab/Sources/Tab/Services/SyncService.swift:947`, `Apps/Tab/Sources/Tab/Services/SyncService.swift:1030`, `Apps/Tab/Sources/Tab/Services/SyncService.swift:1138`, `Apps/Tab/Sources/Tab/Services/SyncService.swift:1258`.
- [ ] Monetary columns are `numeric(20,8)`, allowing 12 integer digits and eight fractional digits. DB allows positive expense/settlement totals and nonnegative child amounts. Currency must be exactly three characters and uppercase, not necessarily from the client catalog. Profile/member names max 60, profile avatar URL max 2048, real trip name nonblank max 100, email lowercase/trimmed with `@` max 320, expense description nonblank max 200, receipt path max 512, note max 200. Category names are nonblank up to 50 characters and icon keys up to 16. Categories enforce default-without-trip XOR custom-with-trip and live custom-name uniqueness case-insensitively per trip. Evidence: `supabase/sql/02_profiles.sql:7`, `supabase/sql/03_trips_people.sql:16`, `supabase/sql/03_trips_people.sql:62`, `supabase/sql/04_categories.sql:4`, `supabase/sql/05_expenses.sql:4`, `supabase/sql/08_settlements.sql:4`.
- [ ] Each live expense must have at least one payment and one split, and each ledger's sum must equal the expense amount exactly. These are deferred transaction-end constraints. People referenced by payments/splits/settlements must belong to the same trip, including removed historical members. Split/payment raw modes allow `equal`, `exact`, `percentage`, `shares`, `adjustment`; share_units is present iff shares and must be positive; percentage is present iff percentage and must be >0 and <=100. The DB checks row totals and metadata shape, not the client's equal/weight/percentage arithmetic. - [ ] Trip kind and creator are immutable. Expense/settlement trip and creator are immutable. ### Sync stamping and delta-pull limits

- [ ] On INSERT, `set_sync_fields` always overwrites `created_at` with `clock_timestamp()`, fills `updated_at` only when null, and fills `write_id` only when null. Column defaults can already provide those values. On UPDATE, a tombstoned row cannot become live. If write ID is unchanged, the server treats it as metadata-less and stamps a fresh `updated_at` and random UUID. Otherwise respect supplied timestamps/UUIDs and compare them. Evidence: `supabase/sql/00_extensions.sql:17`.
- [ ] Live-to-deleted wins without timestamp rejection. Both-deleted compares `deleted_at`, then lexicographically greater UUID text; live-live compares `updated_at`, then lexicographically greater UUID text. Older/equal-lower writes return null from the trigger, meaning a successful REST update can affect zero rows. Full timestamp/UUID equality is accepted by SQL, while the client merge recognizes matching UUID as already converged. Evidence: `supabase/sql/00_extensions.sql:33`, `Packages/TabCore/Sources/TabCore/ConflictResolver.swift:63`.
- [ ] The server does stamp server-side times: `created_at` on inserts, fresh metadata on metadata-less updates, trip `last_activity_at` on expense/settlement writes, activity `timestamp` defaults, joined/removed/revoked times in RPCs, device `last_seen_at`, and clamped seen cursor. It is false that all times are client supplied. However, there is no separate server-received/modified timestamp or monotonic change sequence across every synced row. Client `updated_at` is retained on ordinary explicit writes, child replacement/removal can disappear entirely, and RLS access can disappear. Therefore a universal safe delta pull cannot be built from `updated_at` alone under this contract. An activity timestamp cursor can page activity history but is not a complete ledger/membership deletion feed. Preserve complete reconciliation or prove another client-only strategy correct before replacing it. Evidence: `supabase/sql/00_extensions.sql:26`, `supabase/sql/05_expenses.sql:85`, `supabase/sql/09_activity_log.sql:4`, `supabase/sql/16_rpc_expenses.sql:103`, `supabase/sql/15_rpc_trip_people.sql:288`.
